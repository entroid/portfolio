## Approach

We started from scratch, running workshops with stakeholders and future users to understand business needs and current process pain points. From there we organized basic user journeys and core feature requirements, followed by the first versions of information architecture, feature relationships, and user flows — all mapped collaboratively in Mural. The project moved fast, so we prioritized iterating ideas, presenting, and testing hypotheses quickly over polish.

Wireframes fed into clickable prototypes, which were the real validation instrument: walking a stakeholder through the navigation surfaced structural problems that no static screen ever did. The product has kept going through that loop since — flows, wireframes, prototype, feedback — and several of the decisions below come from later passes, not from the first round.

## Key Product Decisions

**• Scoped the POC to 3 core features** (Impact Comparison Tool, Prioritization Matrix, Data Input Flow), with a multitenant approach, leaving dashboard, analytics, and user management for a future phase — necessary scope control for a fast-moving project.

**• Swapped to *analysis* as the unit of work, instead of the project.** We started grouping items under "Projects" as the main unit of work, while after few iterations it came up that the primary action was creating an "analysis" — two competing object models in the same menu. Reframing the analysis as the container (with projects living inside it) gave the comparison chart somewhere to belong.

**• Froze each analysis's scoring model at creation, with drift detection.** If the organization's weights changed, past results would silently change with them — the exact inconsistency the tool existed to remove. Instead, an analysis keeps the model it was created with, and the system flags when the shared model has moved on, grouping the differences by consequence: what recalculates safely, what needs new data, what would discard existing data.

**• Defined 3 user roles upfront** (Project Owners, Analysts/Contributors, Admin Users), shaping permission and flow decisions from early design rather than as a later patch.

**• Replaced static spreadsheet comparison with a visual, data-driven model** — a bubble chart (more visualization options for later phases) comparing projects by cost, effort, and strategic impact — paired with a traceability panel that breaks down where each project's position comes from, category by category. Without that breakdown, a chart is an opinion shaped like data.

## Notes

- **• Collaborative synthesis in Mural:** stakeholder interviews and workshops were translated into information architecture, brainmaps, and user journeys visually and collaboratively, before touching wireframes.

- **• Wireframes as an exploration tool, not an approval gate:** used to explore layout and data-entry flows, with frequent validation sessions alongside stakeholders and potential users — iterating fast rather than arriving with a locked proposal.

- **• Multi-tenant by design:** "Workspaces" accounted for multiple clients/organizations (including disabled workspace states) as part of the data model from early stages, anticipating the product's use as a service for third parties.

## Deferred to Phase 2

Selection between different models within a workspace, dashboard with tasks, users and workspaces admin, bulk scoring entry, updating model scenarios, analytics and comparing analyses across quarters, permission enforcement for the three defined roles, optional chart visualizations and priorization matrix in the results view. Each was traced, understood, and left out on purpose — the MVP only had to support the first real decision made with the tool.

## Results

Early and continuous MVP feedback showed faster, more intuitive, and data-informed decision-making. Stakeholders kept requesting additional features for the next phase — a signal of strong engagement and perceived value beyond the initial scope.
